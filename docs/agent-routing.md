# Talk to an agent

This experimental native Linux feature delivers a finished dictation to a local coding agent you choose: Claude Code or Codex in Herdr, tmux, any terminal or the background, a Code session of the Claude desktop app, a thread in the Codex desktop app, or a new Claude desktop chat. Mluva finds the sessions itself. How a dictation reaches each one depends on its route, and the session wheel says which before you record. No account is needed, and enabling routing never changes the selected speech provider.

## How a dictation reaches each agent

| Session | Route | What recording does |
| --- | --- | --- |
| Claude Code or Codex in a Herdr pane that Herdr guards | Herdr's guarded prompt | **Send**: typed into exactly that session's composer and submitted, with Herdr's receipt. |
| Any other Claude Code session: a plain terminal, tmux, a Herdr pane Herdr does not guard, a background `claude --bg` session, an Agent SDK host, or a Code session of Claude Desktop | Claude Code's own inbox | **Queue**: admitted to that session's own prompt queue. The agent takes it between tool calls, or as a new turn when it is idle. It arrives as a message from another Claude session, not as typed by you. |
| A live Codex thread: a Codex TUI in any terminal, tmux or Herdr pane, or a thread open in Codex Desktop | Codex's own message queue | **Send if idle**: sent as that thread's next turn and confirmed by it when the thread is idle. A busy, waiting or closed thread gets it withdrawn, and your draft is kept. A thread open in another process takes up to about 10 seconds to pick it up. |
| A new chat in Claude Desktop | A `claude://` link | **Prefill**: Claude Desktop opens a new chat with your text in its composer, and you send it there. This raises Claude Desktop. |
| Anything else | None | **Draft only**: the agent key records an editable transcript in Mluva, with no copy, paste or send. |

Draft only covers Claude Code sessions without an inbox (versions before 2.1.224, `--bare` or `--restricted`), a Codex session Herdr shows but whose thread is not open, and a Herdr pane Herdr cannot send to right now.

Every route keeps the same guarantees. The exact session is checked again immediately before anything is written, and a replaced, restarted, cleared or resumed session is refused, never swapped for a neighbour or a session with the same name. An uncertain delivery is never written again. No route reads terminal contents, uses the clipboard, moves focus or injects keys; the one exception is a new Claude chat, which raises Claude Desktop because you chose it. Typing into a terminal or tmux pane is never used, at any level: it can answer a pending permission prompt, or run your words as editor commands in vim mode.

## Choose a session

Open **Settings → Capture → Agent routing** and enable agent dictation. Changes save automatically. The recipient dropdown appears below the existing editor. Each row gives the session's name, product, project, where it runs and what recording does (Send, Queue, Prefill or Draft only); the tooltip adds its handle and place. The choice is remembered by the session's identity, so a restarted agent, a resumed or cleared Claude Code session, or a Codex thread reopened in another process must be chosen again. Mluva never matches a replacement by name alone.

The configured agent key (F8 by default, configurable to F12) first opens a session wheel without recording or sending. On Omarchy it floats over the focused monitor like Omarchy's launcher, on its own opaque ground with no window frame, drawn as a sundial watch; clicking outside a control dismisses it like Escape. Elsewhere it opens as an ordinary dialog. The first session sits at one o'clock and the rest follow clockwise in discovery order: Herdr's panes in workspace/tab/pane-layout order, then Claude Code sessions outside Herdr in the order they started, then live Codex threads in the order they were opened, then a new Claude chat. Each session is one index on the dial, with its full name and an uppercase key in the room beside its bearing. The watch grows with the number of names and shrinks, never the names, to fit the screen; up to 26 sessions are shown together. A hand and a soft light turn to the remembered session, whose name is larger.

The dial says what the agent key will do for the chosen session: `F12 SEND`, `F12 QUEUE`, `F12 PREFILL` or `F12 DRAFT`, with a line beneath when it matters ("Arrives as a message from another Claude session", "Sends if the thread is idle; otherwise your draft is kept", "Opens Claude with it in a new chat; you send it there", or why it is draft only). A caption under a name says what is worth knowing: **working**, **waiting** (a Claude Code session waiting for your answer, which a queued message waits behind and never answers), **queue**, **prefill**, **draft only**, **blocked** (amber, with Record withdrawn) or **gone** (an empty setting). The dial then says BLOCKED or GONE instead of the record key. Press the key again to record, then again to stop and deliver. Letter keys choose in clockwise order, home row first (A S D F G H J K L, then Q W E R T Y U I O P, then Z X C V B N M). A product appears beside a name for Claude Desktop and Codex Desktop, and wherever sessions of different products share a name; a pane, tmux pane or handle appears only to tell apart sessions with the same name. Left/Right page through more than 26 sessions and Escape cancels. A moved or missing session is never replaced by its neighbour. The normal **Dictate to agent** button and `mluva agents record` retain their direct start/stop behavior.

From the wheel, the normal dictation key (F9 by default) starts a transcript without direct agent delivery. Its provisional destination is Mluva’s editable document: no automatic copy or paste. Press the dictation key again, or Stop, to finish; normal History, Incognito, retention and opted-in account-sharing policies still apply. The [wheel acceptance record](verification/f12-session-wheel/README.md) covers selection, keyboard routing and its limits. Releasing the key or moving focus does not stop recording. Settings → Capture → Global shortcuts contains the normal dictation key, agent key and Keep draft key; each change saves automatically. The assigned desktop binding is displayed there. Both agent keys can be distinct F1–F24 keys, excluding the dictation key and F10.

## Names

A session's name is its agent's own title, shown whole. For Claude Code that is, in order: the name you gave the session (`claude -n`, `/rename`), its latest custom title, then its latest generated title, read from Claude Code's own registry and transcript and matched by session ID. Without those, Mluva shows Herdr's agent label, then the terminal title unless it is only the `--agent` type, then Claude Code's generated handle such as `project-3f`. For Codex it is the thread name in Codex's `session_index.jsonl` (under `$CODEX_HOME`, default `~/.codex`), matched to the exact thread ID; Codex's terminal title is not parsed because its layout is configurable. A Codex thread with no name yet shows its Herdr agent name, else `codex-` and the start of its thread ID. Mluva reads only the ID and name fields of that index and never renames a session. Renaming a conversation inside Codex or Claude Code updates its displayed name without changing the selection.

## Command line

The installed CLI can inspect and switch the running app's recipient, or toggle agent dictation, without opening a window or restarting either application. `mluva herdr` is the same command as `mluva agents`.

```sh
mluva agents list
mluva agents select cos
mluva agents select 0199a1b2-c3d4-7e5f-8a9b-0c1d2e3f4a5b
mluva agents status
mluva agents select w1:p2 --socket /absolute/path/to/herdr.sock
mluva agents clear
mluva agents record
```

Commands print JSON and exit nonzero on failure. Mluva must already be running. Each session reports its `name`, `title`, `kind`, `project`, `status`, Herdr `pane` and `socket` (empty outside Herdr), native `session` ID, `route` (`herdr`, `claude_inbox`, `codex_queue`, `claude_new_chat` or `none`), `delivery` (`send`, `queue`, `prefill` or `draft_only`) and whether it is `available` now. `select` matches a handle, a Herdr pane ID or a session or thread ID, never a title; it discovers a fresh identity, enables routing and updates the live dropdown and saved choice together, and it accepts only sessions Mluva can deliver to. Use an exact pane or session ID for duplicate names, adding `--socket` when multiple Herdr servers match. `status` checks the saved identity against what is running now; a saved name alone does not mean connected. `clear` removes the recipient. A switch request disarms pending automatic delivery and preserves the draft; list, status, select and clear never deliver anything; record starts or stops agent dictation and delivers its finished text. Shortcuts, speech provider and optional spoken status stay unchanged. Incognito changes remain in memory.

## Countdown, outcomes and statuses

Final recognition appears in the normal document editor with a full two-second countdown that says what will happen: **Sending to…**, **Queueing for…** or **Placing in…'s composer**. **Cancel** stops recording, recognition or the pending delivery. **Keep draft**, or **F7**, finishes capture and keeps editable text. Editing, changing recipient, navigating away, a missing or blocked session, screen lock or interrupted timing also disarm automatic delivery. Pressing the agent key again during the countdown, or **Dictate to agent**, ends it and delivers the message at once, once, to the same fixed recipient; that press does not open the wheel. An uncertain delivery is still never replayed. A five-minute recording safety limit stops automatic delivery and retains the draft. Starting an agent recording is refused while a message waits to be delivered: deliver or cancel it first. Starting an ordinary dictation instead stops the pending delivery, and the status says so plainly; the text stays in History. Text longer than a route carries whole (14,336 characters for a new Claude chat) stays a draft rather than being cut.

When an agent or wheel transcript recording starts, Mluva's window switches to the Conversations page so the live text is there whenever you look. It is neither raised nor focused, so the agent keeps the keyboard. If nothing is recognised, the recording is not discarded: it is saved in History with the outcome **no-speech**, and its audio is kept as a failure under your retention choice (not with **Never** or in Incognito, which keep neither a row nor audio) so **Retry transcription** can recognise it again. Ordinary dictation still drops silence.

| Status | Meaning and recovery |
| --- | --- |
| Sent | Herdr acknowledged writing the message and Enter to that session, or the Codex thread took it as its next turn and its own history shows it. Completion is separate. A working agent in Herdr accepts the message without being stopped. |
| Queued | That Claude Code session admitted the message to its own queue. It runs between tool calls, or after the turn. Once queued it cannot be withdrawn. |
| Delivered | The Claude Code session took the queued message into a turn. |
| Held for approval | The session holds messages from other sessions for you to approve (Claude Code's `crossSessionInbound` set to `hold`, or a session in bypass mode). Approve it in that session; Mluva never writes it again, and Send draft stays disabled for this attempt. |
| In the composer | Claude Desktop opened a new chat with the text in its composer. Nothing is sent until you press Enter there. |
| Handing to Codex | Mluva queued the message for the Codex thread and is waiting for it to take it: at once when Mluva talks to the server that has the thread loaded, otherwise up to about 10 seconds. |
| Busy or not open | The Codex thread was working, waiting for you or not open, so the message was withdrawn unsent. Your draft is here; Send draft when the thread is idle. |
| Recipient changed or unavailable | The destination disappeared, changed identity, was renamed or became blocked, or a vim-mode Claude Code composer was not in INSERT mode for Herdr. Keep the draft, choose the intended available session and explicitly send it. |
| Delivery unconfirmed | Some input may already have reached the recipient: Herdr's receipt was lost, a Claude Code session showed no record of the message (it may have refused or dropped it), or a Codex message left the queue without a matching turn. Mluva never resends automatically. Check that session; Send draft stays disabled for this attempt. Copy remains available. |
| Integration needed | Install the reviewed Herdr dependency after approval. There is no legacy prompt, clipboard, key-injection or focus fallback. |
| Interrupted | A lock, suspend, delayed timer or shutdown invalidated the delivery. Relaunch never replays pending messages. |

History records what became of each recorded message in its outcome: `sent`, `queued`, `delivered`, `held`, `prefilled`, `busy`, `draft-kept`, `unconfirmed`, `recipient-unavailable`, `cancelled` or `no-speech`. A queued message that the agent takes later is upgraded from `queued` to `delivered`, watched for up to twenty minutes. Incognito writes none. Local diagnostics, which exclude Incognito, trace the route as `agent-voice` events: wheel opened and closed, recording started and stopped, countdown started, delivery accepted, rejected, unconfirmed or held, a queued message taken, a busy thread, and why a draft was kept. They carry only the step, the route (`wheel`, `guarded-agent` for Send, `queued-agent`, `prefilled-agent` or `transcript`), its outcome and timing: no transcript, session title or credential.

**Send draft** starts a fresh two-second window for the current text and selected recipient. Edits save automatically in the existing conversation store and preserve immutable recognition. Normal retention and account-sharing choices still apply. Routing never copies or pastes automatically, even when ordinary dictation's automatic clipboard settings are enabled.

The selected destination stays fixed during capture; **Mluva never stops or pauses the recipient agent**. Once delivery begins, cancellation cannot retract it; only a Codex message the thread has not taken yet is withdrawn if Mluva closes while it still waits. A failure after a partial write leaves delivery unconfirmed; inspect and clear any pending input yourself. Mluva never sends Escape, Ctrl+C or an answer to a permission prompt.

## Routes in detail

### Herdr

Herdr guards a Claude Code or Codex session in one of its panes whether Herdr launched it, for example with its new-agent tab or `herdr agent start`, or you typed `claude` there yourself. A session you typed needs the native session reported by Herdr's own Claude Code integration, and Herdr must see it idle or working with nothing waiting for your answer. Released Herdr 0.9.1 and unpatched 0.9.5 cannot safely support automatic sending; Mluva shows their metadata and uses another route where one exists. Sending through Herdr needs the [guarded Herdr integration](../integrations/herdr/README.md). Without Herdr's guard, a Claude Code session in a Herdr pane is queued through its inbox and a Codex session is sent if idle through Codex's queue.

With Claude Code's vim key bindings (`editorMode` set to `vim`), Herdr sends only while that session's composer shows `-- INSERT --`. In NORMAL or VISUAL mode it refuses the prompt before writing anything; Mluva reports the recipient unavailable and keeps the text. Press `i` in the session, then **Send draft**. Herdr learns that a session uses vim mode from the indicator Claude Code draws, so hiding it with `hideVimModeIndicator` removes this protection.

### Claude Code's inbox

Claude Code 2.1.224 and later binds one private Unix socket per session for its documented [cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging) and names it in the session's registry entry (`messagingSocketPath`, with `peerProtocol` 1). Mluva writes one message to it: the text, the session's ID and a message ID, and nothing else. The session admits it to its own prompt queue and takes it between tool calls or as a new turn; its composer, a draft you are typing, a permission prompt and a running tool are left alone. A session waiting on a prompt can be queued to; the message waits behind the prompt and never answers it.

Immediately before writing, Mluva reads the registry entry again and requires the same process (its start time unchanged), the same session ID and the same socket; the socket must sit in Claude Code's inbox directory (`$XDG_RUNTIME_DIR/cc-socks`, or `/tmp/cc-socks-<uid>`), owned by you, in a directory only you can enter, and the process answering on it must be that session's own. Claude Code also drops a message meant for another session, so a `/clear` in between loses nothing to the wrong conversation. The socket answers nothing, so Mluva reads what happened from the session's own transcript: the queue admitting exactly this text (**queued**), a turn or queue record carrying the message's ID (**delivered**), or a notice that the session holds it (**held for approval**). Only lines that can be such a record are parsed, compared in memory, and never kept or logged.

The agent sees a dictation delivered this way as a message from another Claude session, "not typed by your user", which Claude Code intends: such a message never counts as your consent and cannot change the session's configuration or run slash commands. Mid-turn, an agent has been seen to read it as a request to answer some other session. If the distinction matters for a session, run it in Herdr with the guarded prompt. A session set to hold messages from other sessions shows a notice and keeps the message for you to approve; one set to refuse them drops it silently, and Mluva reports delivery unconfirmed. Identical messages repeated within a short window are dropped by Claude Code, and at most 50 queued messages are kept.

### Codex's queue

A Codex thread is live only while some process holds its writer lock, `thread-writer-locks/<thread>.lock` under `$CODEX_HOME`; lock files outlive their owners, so a file alone means nothing. Mluva reads the holder from the kernel's lock table, never by taking the lock or resuming the thread, and asks an app server once about each live thread to leave out Codex's own title helpers, sub-agents and threads not started by a person. A thread's state (idle, working, waiting on approval) comes from the server that has it loaded when Mluva talks to that one, else from Herdr, else it shows no state; sending only if idle settles it at send time. A thread held by Codex Desktop's own server is shown as Codex Desktop.

To send, Mluva queues the message for the thread's ID with a fresh client message ID through an app server on the same `CODEX_HOME`, and the process that owns the thread takes it from Codex's shared queue. How soon an idle thread takes it depends on where the thread is loaded. If the server Mluva talks to has it loaded (a TUI attached to the shared daemon), it is taken at once, and Mluva waits three seconds. A thread open in another process (a `--no-daemon` TUI, which is how Herdr runs Codex, or Codex Desktop) is taken only at that process's next check of Codex's queue, which Codex 0.160.1 makes every 10 seconds, so Mluva waits up to 12 seconds, and the status says it is handing the message to Codex meanwhile. It is **sent** once it leaves the queue within that window and the thread's own history shows a user message with that client ID. Otherwise Mluva withdraws it and keeps the draft (**busy or not open**); if it was taken just as it was withdrawn, its turn decides; with no turn to show, delivery is unconfirmed. Mluva never queues a message twice or leaves one behind, never starts, resumes, steers or interrupts a turn, never restarts the queue after you interrupt a turn, never answers Codex's own requests and never writes Codex's files.

Mluva talks to Codex's shared app-server daemon when it runs and answers. Otherwise it starts its own `codex app-server`, listening only on a socket in Mluva's private runtime directory and working in an empty directory there: a child process of Mluva, never an installed service or a managed daemon, stopped after ten idle minutes and when Mluva exits, and offered to no other client, so it hosts nobody's threads. An app server writes Codex's `config.toml` only when a thread is started with full access (it then records the project as trusted) or when asked to change configuration, and Mluva does neither; as a guard, Mluva fingerprints `config.toml` before starting its server and after each use, and if it changed, stops its server for the rest of its run. Codex's queue methods are experimental; a Codex without them leaves its threads draft only.

### Claude Desktop

A Code session of Claude Desktop runs its own bundled Claude Code in the shared registry and is queued to through its inbox like any Claude Code session; the wheel labels it Claude Desktop. Desktop's chats live on claude.ai and nothing local reaches an existing one, so they are not listed. When Claude Desktop is set up for this account (its user data exists and it handles `claude://` links), the wheel offers one more target, **New chat · Claude Desktop**. After the countdown Mluva opens `claude://claude.ai/new?q=<text>` with `xdg-open` (or `gio open`), and Claude Desktop opens a new chat with the text in its composer for you to review and send. Opening the link raises and focuses Claude Desktop, so only this target ever uses it. The text travels in the link, so the system's link opener and Claude Desktop receive it on their command lines. Claude Desktop keeps at most 14,336 characters; longer text stays a draft.

### Finding Claude Code sessions

Claude Code registers each interactive or background process as `sessions/<pid>.json` in its configuration directory: `$CLAUDE_CONFIG_DIR` as set for Mluva, else `~/.claude`. Mluva admits an entry only when that process is alive, its start time matches the one recorded (so a reused process ID is not mistaken for the session) and it runs in Mluva's own PID namespace. The directory and files must be owned by you, must not be symlinks and must not be writable by others; entries are bounded in count and size. Mluva never opens the `.key` files beside them. These files are not a documented Claude Code interface (`claude agents --json` is), so Mluva ignores unknown fields and values rather than failing. Titles come from the newest 1 MiB of each session's transcript on first sight, then only from what was appended; for titles Mluva parses only title and agent-type records, keeps only the title and logs nothing. An entry's `tmux` and `entrypoint` fields say where it runs: a tmux pane, an application such as Claude Desktop, or the background. Mluva's own process and its children are never listed.

## Platforms

Discovery and delivery are implemented and tested on Linux. The model and transports keep platform differences behind one seam (process identity, Claude Code's inbox directory, the peer process check, Codex's lock holders and the link opener). On macOS those answer "unavailable" until each is verified there, so sessions show as draft only rather than being reached by guesswork.

## Optional spoken status

Choose an ElevenLabs voice ID in Settings → Capture → Agent routing and explicitly enable **Speak a brief agent status update**. This uses `eleven_v4_turbo` through Text-to-Dialogue WebSocket, with the same saved ElevenLabs key used by native speech. That key also needs `text_to_speech` permission; a transcription-only key produces a specific error and leaves the text visible. Voice is disabled by default and may incur provider charges. No model substitution occurs.

**Read status** shows one metadata-based sentence about the selected agent. When speech is enabled it also plays that sentence. After an accepted message, one later blocked/done transition can speak once. No route provides correlated response text, so this feature describes activity and never claims that a generic completed turn answered the dictated message. Replay uses the visible sentence; Mute stops playback independently of text status. Sentences are English; Czech voice quality is still an acceptance item.

Only the displayed sentence goes to ElevenLabs: no microphone audio, terminal history or prompt text is read for this purpose. The configured STT provider retains its existing local/cloud semantics. Reply audio is streamed in memory to PipeWire, bounded to 25 seconds/30 seconds of network work, and never saved by the app. A new dictation or Meeting capture cancels and reaps the player before opening audio capture. Incognito suppresses spoken status and creates no Mluva History or retained recording; a recipient can still retain messages explicitly delivered to it.

Remote Herdr servers, browser Unix-socket access and browser-wide hotkeys are outside this native implementation. Physical Wayland shortcut events, microphone feedback and natural English/Czech listening acceptance remain separate from the [isolated evidence](verification/herdr-voice/README.md); the routes added for every agent are recorded in the [universal routing evidence](verification/universal-targets/README.md).
