## Provider matrix

Speech and rewriting are configured independently in **Settings → Providers**. Model discovery is optional; a listed model is not proof that the configured account can run it. See the [selection guide](provider-selection.md) for model aliases and connection settings.

| Task and route | Implemented compatibility | Evidence and deployment limit |
| --- | --- | --- |
| Linux STT · ElevenLabs Scribe | Native realtime plus controlled batch fallback; Meeting diarization still uses ElevenLabs. | Default cloud route. [Native clients](../linux/voice_scribe_linux/realtime.py), [batch client](../linux/voice_scribe_linux/elevenlabs.py). Real provider recordings have [capture provenance](promotion/README.md); they are examples, not a quality benchmark. |
| Linux STT · Voxtype / local Whisper | Runs installed Voxtype in local Whisper file mode. Ordinary dictation recognizes at Stop; Live rewrite enables sequential chunk previews before full-audio reconciliation. | Requires the executable and an installed suitable model. A local JFK fixture run is recorded in the [verification notes](providers-and-live-rewrite.md#verification-boundary); it does not establish quality across languages/models. |
| Linux STT · compatible API | Multipart `POST /audio/transcriptions` with WAV/model and a JSON `text` response. Endpoint, key reference and model are independent of rewriting. | Controlled HTTP tests. Requires an actual transcription deployment: a chat-only endpoint is insufficient. No universal cloud-provider claim. |
| Linux LLM · Codex app-server | Authenticated local client with model discovery, streaming rewrites/titles/cleanup, and Fast only when advertised by that model. | App-server is a client boundary; inference is not necessarily local. Account/model access and credits still apply. [Client](../linux/voice_scribe_linux/codex_client.py), [model selection](../linux/voice_scribe_linux/rewrite_settings.py). |
| Linux LLM · compatible API | Streaming `POST /chat/completions`; optional `GET /models`. Requires a configured text deployment that finishes with `stop`; tool calls and truncated replies fail. | Controlled HTTP tests establish the protocol, not every vendor/account. Mluva neither provisions LiteLLM nor downloads models. |
| macOS source preview | Apple Speech or Google Cloud STT; Gemini Flash cleanup/style/command adapters. | Separate Swift implementation, not parity with Linux provider settings or Live rewrite. No current accepted signed/notarized public binary. [STT factory](../Sources/Services/TranscriptionProviderFactory.swift), [Gemini adapters](../Sources/Services/GeminiFlashRewriteProvider.swift), [macOS guide](macos-development.md). |

The Linux compatible API and Voxtype routes share [provider adapters](../linux/voice_scribe_linux/providers.py) and [controlled transport tests](../linux/tests/test_provider_workspace.py). Local speech alone does not make rewrites or automatic titles local. Hosted compatibility depends on the selected server, deployment, credentials and response protocol.

## Campaign framing

**Direction:** “Best STT built for Omarchy.” Treat this as the product ambition, not a measured ranking. A public formulation is **“Building the best STT experience for Omarchy.”** Pair it with concrete behavior: **“Speak a rough idea. Shape it into useful text. Keep the original.”**

Show existing-text polish, a clearly labeled Live draft, the floating note opening into editable text, searchable history, local export and independent provider settings. Label offline feature captures **“Feature walkthrough · example text”**. The accompanying media README and manifest must disclose the production UI with synthetic text and a local provider fixture, and distinguish it from real-provider footage. Use source/release labels that match each capture. Do not infer speed, accuracy, universal compatibility or live-desktop acceptance from a fixture.
