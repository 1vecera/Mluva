# Talk to a Herdr agent

This experimental native Linux feature sends a finished dictation to a selected local Codex or Claude Code session. Sending needs the [guarded Herdr integration](../integrations/herdr/README.md). Finding sessions does not: Mluva lists every Claude Code session from Claude Code's own session registry, with or without Herdr, and every Codex or Claude Code session Herdr reports. Sessions Mluva cannot send to are draft-only (see [Sessions outside Herdr](#sessions-outside-herdr)). Released Herdr 0.9.1 and unpatched 0.9.5 cannot safely support automatic sending; Mluva shows their metadata but disables delivery. No account is needed, and enabling routing never changes the selected speech provider.

Open **Settings → Capture → Agent routing** and enable agent dictation. Changes save automatically. The recipient dropdown appears below the existing editor. Choose a session by its name, agent type, project and pane; the full local socket is included in its tooltip to distinguish servers. The choice is remembered, but a restarted agent, or one renamed in Herdr, must be selected again. Mluva never matches a replacement by name alone.

A session's name is its agent's own title, shown whole. For Claude Code that is, in order: the name you gave the session (`claude -n`, `/rename`), its latest custom title, then its latest generated title, read from Claude Code's own registry and transcript and matched to the session ID Herdr reports. Without those, Mluva shows Herdr's agent label, then the terminal title unless it is only the `--agent` type, then Claude Code's generated handle such as `project-3f`. For Codex it is the thread name in Codex's `session_index.jsonl` (under `$CODEX_HOME`, default `~/.codex`), matched to the exact session ID Herdr reports; Codex's terminal title is not parsed because its layout is configurable. Mluva reads only that index's ID and name fields and never renames a session. A Codex session with no title yet shows its Herdr agent name, or its pane ID. Renaming a conversation inside Codex or Claude Code updates its displayed name without changing the selection. `mluva herdr list` reports both `title` and Herdr's `name`; `select` matches the Herdr name or pane ID.

The installed CLI can inspect and switch the running app's recipient, or toggle agent dictation, without opening a window or restarting either application:

```sh
mluva herdr list
mluva herdr select cos
mluva herdr status
mluva herdr select w1:p2 --socket /absolute/path/to/herdr.sock
mluva herdr clear
mluva herdr record
```

Commands print JSON and exit nonzero on failure. Mluva must already be running. `select` discovers a fresh guarded identity, enables routing and updates the live dropdown and saved choice together. Use an exact pane ID for duplicate names, adding `--socket` when multiple servers match. Unavailable or ambiguous recipients are rejected. `status` checks the saved identity against the current server; a saved name alone does not mean connected. `clear` removes the recipient. A switch request disarms pending automatic delivery and preserves the draft; list, status, select and clear never send a prompt; record starts or stops agent dictation and sends its finished text. Shortcuts, speech provider and optional spoken status stay unchanged. Incognito changes remain in memory.

The configured agent key (F8 by default, configurable to F12) first opens a session wheel without recording or sending. On Omarchy it floats over the focused monitor like Omarchy's launcher, on a dimmed desktop with no window frame; clicking outside a control dismisses it like Escape. Elsewhere it opens as an ordinary dialog. The first session in Herdr workspace/tab/pane-layout order, the leftmost pane, sits at one o'clock; the rest follow clockwise, each name in full beside its mark. Claude Code sessions outside Herdr follow the Herdr panes in the order they started. The ring and window grow with the number and length of names, up to the screen, before a name would wrap more tightly; up to 26 sessions are shown together. The remembered session is highlighted and named in the centre with its status and record key. Press the key again to record, then again to stop and send. Letter keys choose in clockwise order, home row first (A S D F G H J K L, then Q W E R T Y U I O P, then Z X C V B N M). Pane IDs, or for sessions outside Herdr Claude Code's handle, appear only to tell apart sessions with the same name. Blocked or missing sessions are marked unavailable; draft-only sessions are marked with a square and **draft only**. Left/Right page through more than 26 sessions and Escape cancels. A moved or missing session is never replaced by its neighbour. The normal **Dictate to agent** button and `mluva herdr record` retain their direct start/stop behavior.

From the wheel, the normal dictation key (F9 by default) starts a transcript without direct agent delivery. Its provisional destination is Mluva’s editable document: no automatic copy or paste. Press the dictation key again, or Stop, to finish; normal History, Incognito, retention and opted-in account-sharing policies still apply. The exact alternate destination awaits confirmation; it is isolated from agent routing. The [wheel acceptance record](verification/f12-session-wheel/README.md) covers selection, keyboard routing and its limits. Releasing the key or moving focus does not stop recording. Settings → Capture → Global shortcuts contains the normal dictation key, agent key and Keep draft key; each change saves automatically. The assigned desktop binding is displayed there. Both agent keys can be distinct F1–F24 keys, excluding the dictation key and F10.

Final recognition appears in the normal document editor with a full two-second **Sending to…** countdown. **Cancel** stops recording, recognition or the pending send. **Keep draft**, or **F7**, finishes capture and keeps editable text. Editing, changing recipient, navigating away, a missing/blocked session, screen lock or interrupted timing also disarm automatic sending. Pressing the agent key again during the countdown, or **Dictate to agent**, ends it and sends the message at once, once, to the same fixed recipient; that press does not open the wheel. An uncertain submission is still never replayed. A five-minute recording safety limit stops automatic sending and retains the draft. Starting an agent recording is refused while a message waits to send: send or cancel it first. Starting an ordinary dictation instead stops the pending send, and the status says so plainly; the text stays in History.

When an agent or wheel transcript recording starts, Mluva's window switches to the Conversations page so the live text is there whenever you look. It is neither raised nor focused, so the agent keeps the keyboard. If nothing is recognised, the recording is not discarded: it is saved in History with the outcome **no-speech**, and its audio is kept as a failure under your retention choice (not with **Never** or in Incognito, which keep neither a row nor audio) so **Retry transcription** can recognise it again. Ordinary dictation still drops silence.

History records what became of each recorded message in its outcome: `sent`, `draft-kept`, `unconfirmed`, `recipient-unavailable`, `cancelled` or `no-speech`. Incognito writes none. Local diagnostics, which exclude Incognito, trace the route as `agent-voice` events: wheel opened and closed, recording started and stopped, countdown started, send accepted, rejected or unconfirmed, and why a draft was kept. They carry only the step, the route (`wheel`, `guarded-agent` or `transcript`), its outcome and timing: no transcript, session title or credential.

**Send draft** starts a fresh two-second window for the current text and selected recipient. Edits save automatically in the existing conversation store and preserve immutable recognition. Normal retention and account-sharing choices still apply. Routing never copies or pastes automatically, even when ordinary dictation's automatic clipboard settings are enabled.

| Status | Meaning and recovery |
| --- | --- |
| Sent | Herdr acknowledged writing the message and Enter to the same agent. Completion is separate. Working agents can accept the message without being stopped. |
| Recipient changed or unavailable | The destination disappeared, changed identity, was renamed or became blocked, or a vim-mode Claude Code composer was not in INSERT mode. Keep the draft, choose the intended available session and explicitly send it. |
| Delivery unconfirmed | Some input may already have reached the recipient. Mluva reads the receipt but never resends automatically. Check that session in Herdr; Send draft stays disabled for this attempt. Copy remains available. |
| Integration needed | Install the reviewed Herdr dependency after approval. There is no legacy prompt, clipboard, key-injection or focus fallback. |
| Interrupted | A lock, suspend, delayed timer or shutdown invalidated the send. Relaunch never replays pending messages. |

The selected destination stays fixed during capture; **Mluva never stops or pauses the recipient agent**. Once submission begins, cancellation cannot retract it. A guard failure after a partial write leaves delivery unconfirmed; inspect and clear any pending recipient input yourself. The client does not send Escape, Ctrl+C or an answer to permission prompts.

## Sessions outside Herdr

Herdr's guarded prompt is the only way Mluva sends. Herdr guards a Claude Code session in one of its panes whether Herdr launched it, for example with its new-agent tab or `herdr agent start`, or you typed `claude` there yourself. A session you typed needs the native session reported by Herdr's own Claude Code integration, and Herdr must see it idle or working with nothing waiting for your answer. Sessions found only in Claude Code's registry because they run outside Herdr are listed but draft-only, and so are Herdr panes that miss those checks. Choosing one on the wheel shows **Record draft** and "Draft only: it runs outside Herdr" or "Draft only: Herdr can't send to it now". The second agent key then hides the wheel and records into Mluva's editable document exactly like the wheel's dictation key: no copy, paste or send. The next agent key press stops it. **Dictate to agent**, **Send draft** and `mluva herdr record` stay disabled for such a session, and `mluva herdr select` still accepts only sessions Mluva can send to.

With Claude Code's vim key bindings (`editorMode` set to `vim`), Herdr sends only while that session's composer shows `-- INSERT --`. In NORMAL or VISUAL mode it refuses the prompt before writing anything; Mluva reports the recipient unavailable and keeps the text. Press `i` in the session, then **Send draft**. Herdr learns that a session uses vim mode from the indicator Claude Code draws, so hiding it with `hideVimModeIndicator` removes this protection.

Claude Code registers each interactive process as `sessions/<pid>.json` in its configuration directory: `$CLAUDE_CONFIG_DIR` as set for Mluva, else `~/.claude`. Mluva admits an entry only when that process is alive, its start time matches the one recorded (so a reused process ID is not mistaken for the session) and it runs in Mluva's own PID namespace. The directory and files must be owned by you, must not be symlinks and must not be writable by others; entries are bounded in count and size. Mluva never opens the `.key` files beside them. These files are not a documented Claude Code interface (`claude agents --json` is), so Mluva ignores unknown fields and values rather than failing. Titles come from the newest 1 MiB of each session's transcript on first sight, then only from what was appended; Mluva parses only title and agent-type records, keeps only the title and logs nothing. Mluva's own process and its children are never listed. A choice of a session outside Herdr is remembered by session ID and process, so a resumed session in a new process must be chosen again.

## Optional spoken status

Choose an ElevenLabs voice ID in Settings → Capture → Agent routing and explicitly enable **Speak a brief agent status update**. This uses `eleven_v4_turbo` through Text-to-Dialogue WebSocket, with the same saved ElevenLabs key used by native speech. That key also needs `text_to_speech` permission; a transcription-only key produces a specific error and leaves the text visible. Voice is disabled by default and may incur provider charges. No model substitution occurs.

**Read status** shows one metadata-based sentence about the selected agent. When speech is enabled it also plays that sentence. After an accepted message, one later blocked/done transition can speak once. Herdr currently provides no correlated response text, so this feature describes activity and never claims that a generic completed turn answered the dictated message. Replay uses the visible sentence; Mute stops playback independently of text status. Sentences are English; Czech voice quality is still an acceptance item.

Only the displayed sentence goes to ElevenLabs: no microphone audio, terminal history or prompt text is read for this purpose. The configured STT provider retains its existing local/cloud semantics. Reply audio is streamed in memory to PipeWire, bounded to 25 seconds/30 seconds of network work, and never saved by the app. A new dictation or Meeting capture cancels and reaps the player before opening audio capture. Incognito suppresses spoken status and creates no Mluva History or retained recording; a recipient can still retain messages explicitly sent to it.

Remote Herdr servers, browser Unix-socket access and browser-wide hotkeys are outside this first native implementation. Physical Wayland shortcut events, microphone feedback and natural English/Czech listening acceptance remain separate from the [isolated evidence](verification/herdr-voice/README.md).
