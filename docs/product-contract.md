# Product behavior and privacy

Mluva turns speech into editable text and delivers it to the selected destination while retaining the original recognition. Omarchy is the primary, daily-used platform; [desktop support](linux-platform-profile.md) and [feature status](feature-maturity.md) describe the supported workflow and experimental capabilities.

## Recording and editing

The recording shortcut toggles capture. A second press during preparation cancels before recording starts. Mluva checks the selected input and required provider readiness before opening the microphone. The microphone remains in Preparing until its first complete PCM sample arrives, including silence; an input that closes or supplies no sample within three seconds fails without claiming to record. Phone input acknowledges its prepared stream before the phone starts sending. PipeWire audio is captured as private 16 kHz, 16-bit mono PCM.

A successful recognition with no speech completes quietly. It does not copy, paste, create a blank history entry or replace the current conversation. Silent audio follows the successful-capture retention policy; Incognito erases it. Malformed responses, network errors and capture failures still use the normal recovery path.

Scribe displays live recognition but only committed text becomes raw history or final dictation delivery. If realtime recognition cannot start or finalize, the app reports the batch fallback explicitly. Local and compatible batch providers can show provisional chunk previews; the complete recording is recognized at Stop.

Raw recognition, working edits and delivered text remain separate. Editor changes autosave after a short pause, updating only the working version. Copy remains visible; there is no Save button. Failed saves keep the draft and retry, and normal Quit flushes pending edits. Smooth following is on, honors system reduced motion and stops following when the user deliberately scrolls away.

There is one normal dictation mode. Polish, manual and live rewriting, prompts/templates, generated titles, Notes and Command capture modes are removed, including their clients, schedulers and controls. Old saved rewrites remain editable and exportable. The separate Meeting recorder still explicitly records the selected microphone and output sink's monitor; system audio means everything playing through that sink. Partial-source failures are reported. Meeting remains Experimental.

## Providers and credentials

The selected speech provider determines where audio is recognized. Explicit cloud speech sends audio to that provider. The three app-managed local models keep recognition local, load only while transcribing and never use a paid fallback. Mluva has no built-in text-generation provider. Herdr sessions use their own agent settings after explicit routing.

Credentials enter through the application process environment or an existing managed launcher. Settings stores variable names, not values. Credentials are excluded from history, diagnostics and shell previews. ElevenLabs batch uploads and compatible endpoints reject redirects so credentials and recordings stay at the configured endpoint. Compatible endpoints reject embedded credentials; HTTPS is required except for loopback servers. [Provider setup](provider-selection.md) explains connection settings.

## Clipboard and insertion

Completed ordinary dictation copies automatically. Approved global capture also attempts insertion into the exact captured, restorable, nonsecure target. Manual main-window and widget capture are copy-only because focusing those controls cannot establish the intended destination. Unavailable or changed targets fall back to the clipboard. Uncertain insertion never retries through a second route. Copy uses the current editor text; autosave changes storage without contacting a speech provider or changing the clipboard. Copy as path explicitly copies a private Markdown path containing the dictation and linked local images.

Chromium insertion preserves its actual highlight instead of restoring unreliable Unicode offsets. Changed fields or selections become copy-only. Insertion that cannot be confirmed keeps an unconfirmed receipt and never triggers a retry. Dictation does not read arbitrary target text. See [browser delivery limits](verification/browser-direct-transport/README.md#chromium-selection-preserved-for-automatic-delivery).

## Local history and recovery

Explicit screenshots belong to the recording or selected conversation. The Omarchy region picker leaves the clipboard unchanged. PNGs remain editable in Tensaku; narration can create spoken text boxes. Screenshots stay local and are no longer submitted to a built-in rewrite provider. Incognito rejects screenshot capture. Limits remain eight screenshots, 8 MiB per image and 24 MiB total. Images are retained, merged, removed and pruned with their conversation. Completed selections from interrupted recordings remain recoverable; unfinished selections are cancelled.

Settings and saved work use the XDG config/data directories with owner-only state. History retains raw recognition and completed working versions, instructions, provider/model metadata and timestamps. Search covers saved conversations. Markdown and JSON exports contain raw recognition, saved source and completed replies.

Settings form one continuous page, with Account & devices first. The section selector jumps within that page and follows scrolling; command search expands and focuses the original preference row. Feature maturity has no settings section. Removing that informational section changes no feature availability, defaults or saved preferences.

Audio retention follows the selected policy. Recognition failures can retain recovery audio when allowed; retry validates that it belongs to managed storage and produces a preview without automatic copying or insertion. Deletion and retention pruning also remove associated conversations and replies. Path ownership checks prevent arbitrary files from being adopted as recovery audio.

Sidebar actions rename, merge or delete saved conversations; clicking a chat title edits it in place. Merging preserves immutable originals and saved replies, combines the current working versions in the selected order, and keeps one sidebar entry under the destination title. Original recordings remain in History and exports. Confirmation is required for merge and deletion; deletion and retention cover the complete combined conversation. These local actions do not invoke a provider or copy text.

Titles use a local transcript label unless manually renamed; no text is sent for title generation. Existing titles remain intact.

On upgrade, known retired settings are ignored without resetting speech, language, device, privacy or retention choices. Inert saved styles remain in personalization data; old prompt files are left untouched. A valid unfinished Notes draft migrates to local History before pruning. A transaction marker makes replay idempotent and prevents resurrection after deletion. Newer working edits win; malformed recovery files remain available for repair. Incognito drafts are erased, including owned audio. This migration neither sends text nor queues account uploads.

Incognito saves no new history or recovery audio. Dictation, meeting source files and batch preview chunks use a private memory-backed `/dev/shm` directory, with no disk-directory fallback. An independent cleanup process removes it when Mluva exits or is killed; reboot also clears the volatile filesystem. This does not control operating-system swap or crash dumps. Recognition still uses the chosen speech provider; cancellation cannot recall audio already sent to a cloud service.

## Screen annotation

Experimental [screen annotation](screen-annotation.md) is off by default and enabled in Settings → Capture; it applies to ordinary and agent dictation, not phone recordings. While an annotated recording runs on Hyprland, Mluva adds temporary non-consuming Shift and consuming Shift-click bindings and a click-through layer-shell overlay; ordinary input reaches applications. Bindings are removed at Stop, cancellation, failure and Quit, and by an independent watchdog if Mluva exits. Existing Shift bindings disable annotation for that recording. Elsewhere, only Mluva's annotation application actions drive the overlay.

Stopping is unchanged. A recording without marks, or without recognized speech, behaves exactly as before and keeps no bundle. A marked recording writes a private bundle of 6–12 keyframes, fewer when there are fewer distinct moments, plus a contact sheet, `summary.md` and `annotation.json`. Each mark gesture keeps its own keyframe. Frames are grabbed clean and the ink is composited afterwards. The delivered message is the dictation followed by the summary with absolute frame paths, through the existing exact-target, clipboard or guarded Herdr route and its checks and cancel window; agent drafts keep the summary. Raw recognition is unchanged, and the working text and History hold only the dictation. Bundles stay local, never enter account sync, and are retained, merged, pruned and deleted with their conversation; interrupted bundles are recovered into History. Raw frames live in the private runtime directory only until the bundle is written. Incognito never annotates.

## Optional account continuity

The main toolbar's Account sync icon opens Account & devices directly; its tooltip reflects the current account status. Settings → Account & devices remains available. Sign in with browser opens Cognito with PKCE and a ten-minute state-bound `mluva://account` callback. The browser return opens the account panel so connection status or a recovery message is visible. Credentials use the existing Secret Service (`secret-tool`); an unavailable keyring permits a session-only login with a visible explanation. Nonsecret host configuration and per-account device choices are cached for reconnect. Login never changes native speech settings, local models or audio retention. Native capture still works signed out and offline.

New native recordings are shared only when “Sync new recordings automatically” is enabled. Previously private history requires the explicit “Share the open conversation” confirmation. Once shared, saved edits, titles, completed rewrites and original recording segments sync through one revisioned account note. Native microphone audio, retained files, screenshot pixels, local paths, provider credentials and model settings are excluded from account documents and live requests. An explicitly selected native cloud provider remains a separate user choice.

Receivers are named and selected explicitly. Volatile live words have ordered sequence numbers and acknowledgement retry; they do not trigger native clipboard or insertion. The durable note is the recovery path if a receiver misses live updates. Native previews are speculative until final recognition. Native sync persists a frozen edit/revision/operation ID, and web recovery stores its equivalent in account-scoped IndexedDB. Concurrent edits require a visible choice; original recognition cannot be replaced. Continued recordings and merges preserve original segments, with merged source history retired atomically on the account. Tombstones prevent late saves from resurrecting deleted notes.

Sign-out cancels sync, removes downloaded account notes and clears keyring credentials while retaining original local recordings, models and settings. If offline revocation cannot reach the server, the UI asks the user to remove that device from another signed-in device. Removing a device blocks its existing tickets, live connection and history access even while its access JWT has time remaining. Signing in afresh can register a new device; lost-account control still requires changing account credentials. Incognito pauses native account traffic and imports; the browser disables live sync, history and recovery persistence for its new words.

The installable web workspace provides recording/Stop/Cancel, continuation, editing, immutable originals, searchable history, rename, merge, deletion, copy/export, device settings, privacy and recovery. New captures use normal dictation and save when finalized; subsequent text and title edits autosave while history is enabled. Edits made during a web request remain editable and become the next revision, with frozen retries and explicit conflict resolution. Old notes keep their original mode metadata and saved replies. There are no rewrite controls, task templates or generation route. The AWS template no longer grants Bedrock invocation.

Browser microphone PCM goes directly to Scribe with a short-lived server-minted token; account history and fan-out receive text only. Browser permissions, suspension and clipboard gesture requirements apply. Arbitrary-window insertion, global shortcuts, system-audio meeting capture and screenshot narration remain native workflows. Offline microphone transcription and background recording are not promised. Public speech retains its opt-in/latency gate; this simplification does not enable or deploy it. The [account cutover plan](verification/account-sync/cutover.md) retains the installed bridge until approved replacement acceptance.

## Desktop integration and diagnostics

Experimental [Herdr voice routing](herdr-voice.md) is enabled in Settings → Capture, alongside its shortcuts. The agent shortcut first opens a keyboard session wheel, floating over the desktop as an overlay where the compositor supports layer-shell, remembering the guarded selected identity: the leftmost Herdr pane sits at one o'clock and later panes follow clockwise in Herdr order, each shown by its agent's own full session title. A second press starts capture for that same session; Escape cancels selection. Letter keys in clockwise order, home row first, and arrow paging beyond 26 sessions permit mouse-free selection. From the wheel, the normal dictation shortcut provisionally records an editable Mluva transcript without automatic clipboard, insertion or agent send. Missing/replaced sessions never become a neighbour or same-name replacement. Press **Dictate to agent** or `mluva herdr record` to start directly, then press again to stop. The exact local destination stays fixed while recording; final recognition sends after a full two-second cancel window. Editing, changing recipient or an interruption keeps a draft. Settings save automatically. Routing preserves the selected STT route and immutable recognition, and suppresses ordinary automatic copy/paste for this capture. A guarded server method and operation receipt are required; unavailable legacy transport never falls back to foreground input. Working agents remain running, blocked agents require attention in Herdr, and an uncertain submission is never replayed automatically.

Optional ElevenLabs v4 Turbo speaks only one visible metadata status sentence, with explicit opt-in and TTS permission. It does not inspect terminal history or send microphone audio for speech output. Acceptance is distinct from agent completion. Incognito suppresses speech output; starting native dictation or Meeting cancels and reaps playback before capture. The [verification record](verification/herdr-voice/README.md) identifies the separate Herdr dependency and physical/device/provider limits.

The optional [browser recorder](browser-recorder.md) accepts authenticated device recordings through Cloudflare Access and Tunnel. Live microphone mode streams ordered PCM into the native recording session, automatically showing the desktop widget without opening the PC microphone or focusing the main window. Either device can Stop; the native speech provider, clipboard and retention rules apply. The optional send-at-Stop inbox uses Scribe v2 and saves recognition in local History before it is reused across browser devices. It can be added to a phone’s home screen as a standalone web app, with Record / Stop as the main action. Installation keeps the same Access gate and requires an online PC; it does not add background recording or cache authenticated responses. Its own audio staging, browser-local recovery, clipboard behavior and Incognito limits are described in that guide. Native installation does not enable this service.

Shortcuts are approved by the desktop portal. The Omarchy widget receives a bounded volatile preview through the local bridge. It neither persists text nor holds credentials or calls providers. Its rewrite, review and countdown controls are removed; recording ends at final delivery. Shift+F9 opens the latest editor.

Diagnostics exports contain bounded event categories, timings and nonsecret configuration flags. They exclude audio, transcript text, selected text, clipboard contents, device names, application/window identities, credentials and arbitrary provider error messages. Incognito writes no diagnostic events.

Native installation checks ownership before replacing files and preserves the previous app until its installation succeeds. The combined setup checks plugin customizations first; a later widget failure leaves the successfully installed native app available and reports how to retry. Upgrades keep settings and conversations; uninstall retains user-created data. See the [installation guide](../linux/README.md#install-for-the-current-user) and [migration behavior](identity-migration.md).
