## Bounded next acceptance work

Physical/device evidence remains required: installed 2.1.0 F9 with the real microphone, F10 while the main recording continues, a fresh narrated Tensaku phrase and a saved readable text box. Selected microphone/system-audio capture and the desktop's actual shortcut/permission path require the corresponding real devices. Synthetic audio, a compositor action and daily use reported without those specifics cannot certify them.

The original review identified current Wayland app/widget behavior and direct-transport browser privacy as the next automated gaps. The subsequent comparisons above cover the joined widget and Firefox default transport with a real outgoing-read observer and positive controls. Remaining concrete browser work is Chromium activation and correct Unicode selection handling, followed by assembled Chromium workflows. Existing GTK/Firefox owners also name discovery/ambiguity limits not reached by their corpus. Add evidence at those boundaries rather than repeating the already-passing entire workspace for each documentary change.

Fedora GNOME and clean-distribution checks remain external environment gaps. The repository retains compatibility without claiming current acceptance. No GNOME Shell binary is available here, and successful execution on the build host cannot certify another distribution's GTK/WebKit/ONNX dependencies. This does not authorize dropping the platform contract.

Performance comparison work already measures the requested startup, memory, CPU and interaction categories. Native startup and resident memory improve in the named isolated warm-cache series. UI and resident-inference ranges often overlap; no further benchmark is needed merely to manufacture a larger speed claim. Renew a measurement when a relevant runtime change, regression or unmeasured claim justifies it.

The full parity goal remains active. Daniel authorized merging the relevant open PRs on 6 October; this batch does not publish a release, replace the installation, change feature maturity or declare full parity. Installed 2.1.0 and its settings/History remain untouched. The next implementation change should be driven by a reproduced defect or a concrete uncovered contract, not by an unlimited checklist of hypothetical combinations.
