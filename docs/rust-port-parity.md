## Current state

30 September 2026: PRs #66/#67 and release packaging #68 merged; 1.6.0 published with checksum-verified source and editor assets. The local app/widget upgrade passed settings, history, editor and desktop-preservation checks. Created the Rust worktree from remote main and started an unbudgeted Rust-port goal. Linear search found no existing Mluva Rust-port issue. No delegation or new Linear ticket was created.

The native Rust core now implements all persisted settings, migrations, XDG paths, owner-only atomic writes and deterministic spoken structure. [Frozen outputs](../rust/mluva-core/tests/fixtures/README.md) from the exact release cover 357 settings cases, four XDG environments and 6,540 transcript cases. These checks caught and resolved nullable remote-model and unbounded integer compatibility gaps. The final component review also rejected URLs without an authority and froze the reference's Unicode word classification so library updates cannot change spoken-command boundaries. Native filesystem checks cover permission repair, refusal to overwrite damaged settings and temporary-file cleanup. This is component evidence; the complete workflows remain pending until integrated and verified through the native UI.

## Evidence rules

Use the unchanged 1.6.0 release and its external test boundaries as the comparison oracle. Reference Python may run only from a separate frozen baseline during development and must not ship with or be required by Rust. Preserve synthetic recordings/images and logs privately in `tmp/`; publish only curated evidence with no user content, settings values, application/window names or credentials.

Physical F9/F10, the user's microphone and simultaneous real-microphone recording remain unverified in the reference. A simulated command or synthetic audio cannot establish those checks. These limits do not authorize dropping the corresponding implementation or changing its user experience.
