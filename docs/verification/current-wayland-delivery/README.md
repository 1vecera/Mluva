The installed Rust 2.1.0 executable and unchanged v1.6.0 at `5202477edfe4b5d8bacfa5b2e9fd6eadd9624f7f` pass the same six recording workflows. A separate raw-terminal observer records actual input in two real Ghostty 1.3.1 windows. This joins the packaged application, public recording actions, recognition, transcript processing, clipboard, exact window/process capture, keyboard delivery and History; the earlier [Ghostty repair](../ghostty-format-paste/README.md) exercised the delivery component and Codex attachment separately.

Each implementation starts twice, closes its workspace through the private compositor's ordinary close request, remains resident, and quits normally twice. The observer invokes public `global-record`, `record`, `cancel` and `quit` actions. Every capture uses the production recorder with a separate native PCM peer in place of `pw-record`; actual multipart HTTP uploads reach a private loopback speech endpoint. Each response is held until its processing state has been observed. Recognition returns a Czech/emoji phrase containing the spoken `new line` command; raw recognition retains that command and delivered text contains the newline.
