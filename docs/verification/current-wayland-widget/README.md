## Actual joined workflows

Each app runs in a separate private Wayland session with its real executable, GTK window, GApplication actions and shell bridge. Quickshell loads the byte-unchanged released widget and the installed Omarchy Commons/Ui controls in a small test bar/editor. Hyprland applies the widget's actual production floating/pinned/no-initial-focus rule; no `hyprctl` stub or substitute status publisher is used. Read-only fixture IPC observes QML properties and button geometry; the private pointer clicks enabled production buttons. It combines their window-relative coordinates with actual compositor window positions. A private GTK accessibility observer selects the older sidebar note and confirms its immutable original is displayed.

Twenty-three states cover initial readiness; global recording without focus theft; held transcription; completed review and explicit Copy; opening another note; widget Polish targeting the recorded note; held/completed rewriting without automatic copying; explicit reply Copy; More; module removal/recreation and actual bridge replay; compositor reload; Structure and Cancel; a late cancelled reply; continued recording and its immutable child/source/reply linkage; Open; normal Quit; restart without stale review; and final Quit. The retained older note stays byte-identical in every database snapshot.

The candidate matches every observed widget property, clipboard value, focus endpoint and complete five-table SQLite snapshot against the reference. Only generated UUIDs, generated UTC timestamps and measured recognition milliseconds are normalized, with their types, validity and links checked independently. All 23 History columns and the complete source/reply/screenshot/continuation schemas are compared. The installed version differs at the two continued-recording/processing states; the candidate fixes both. While recording, the reference buffers an empty WAV and native writes 3,244 bytes immediately; held uploads contain identical 16 kHz mono 16-bit PCM. Successful completion leaves no retained WAV.

The speech and rewrite endpoints are real loopback HTTP peers on the private network. Two actual multipart WAV uploads and two exact compatible rewrite/SSE requests are compared. The configured model is selected explicitly; no catalog discovery occurs. Cancelled output never creates a second reply or changes the clipboard. Synthetic PCM and provider responses establish application/transport behavior, not actual microphone or model quality.
