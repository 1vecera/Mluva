## People and acceptance

These personas are assumptions inferred from Daniel's notes and the existing product, not findings from user research.

| Person and journey | Failure that matters | Observable acceptance |
| --- | --- | --- |
| An Omarchy user dictates a task while another application stays active, then opens Mluva. | Recording is ambiguous, the preview distracts, or opening the workspace loses text. | A fixed-center red light and timer identify recording; Stop remains named and reachable. The floating surface retains five lines and the full original stays available in the workspace. |
| A writer enables Live rewrite, reads earlier lines, corrects a draft and stops. | Wrapping shifts the panes; scrolling overrides reading; final reconciliation overwrites an edit. | Pane widths remain equal and fixed through wrapping, scrolling anticipates the next line, manual reading suspends following, and final reconciliation preserves the edit. |
| A writer edits a formatted reply, copies it and saves it for later. | Styling changes stored text, hidden syntax disappears, or an incomplete reply is mistaken for a final result. | Exact Markdown, Unicode and whitespace survive explicit Copy and Save. Raw recognition stays literal and separately recoverable. Partial rewrite previews cannot be copied or saved as completed replies. |
| A keyboard user opens Ctrl+P from an editor and chooses an action. | Focus is lost, selection moves off screen, or a stale command affects another note. | Search, native row navigation, Enter and Escape work; the selected row stays visible. Commands recheck the same visible conversation/editor and availability before dispatch. |

## Design choices and review corrections

Equal Live panes use a 24-pixel gap and stack at the existing compact breakpoint. Reserved scrollbar gutters keep text clear without changing width when a track appears. The GTK follower adds proportional room after the current line is 72% full; the inspected fixture moved six pixels before its next wrap, with 46 pixels of lookahead. Manual scrolling and reduced-motion settings retain their existing meaning.

Markdown stays in one native text buffer. Formatting hides delimiters for reading and reveals them on focus; explicit document actions read the unchanged source. This keeps editing, selection and persistence together without introducing a web renderer. Very dense formatting falls back to complete plain Markdown after 2,048 spans, and tokens longer than 1,024 characters use character wrapping to avoid Pango's repeated word search. Ordinary prose retains word wrapping and restrained formatting.

Independent security review found and verified fixes for two concrete defects: quadratic delimiter parsing and commands that could target a hidden conversation. The replacement scanner processed 120,000 malformed characters in about 29 ms in the independent parser/projection probe; 20,000 randomized Unicode cases preserved span invariants. Native formatting and layout are measured separately because parser speed alone does not establish responsiveness.

Independent usability review found missing accessible names for command search and the Live panes. The final private AT-SPI tree exposes Search actions, Dictation, Live draft and Recording Stop. A separate keyboard probe verified search Down, Tab into the selected row, native Down, and Enter dispatching exactly once before focus returned to the editor. A suspected header Close-button conflict was not reproduced; it is not counted as a confirmed defect. Custom Enter/arrow handling is limited to search so native controls retain their own behavior.

The command regression also reproduced a selected action below the visible list. Selection now clamps the scroll adjustment to the row while search retains focus. Stale-target checks cover another conversation, another editor with the same conversation ID, transient content and Incognito; edits within the same editor remain copyable. A fresh empty workspace disables document actions until there is a document to use.

Independent architecture review found excess height with CRLF line endings, clipped nested lists, Unicode no-break text that bypassed the wrapping guard, and styled Unicode separators that broke measurement. Simplified indentation and native-compatible paragraph boundaries resolve these cases. All 84 geometry cases retain 26 pixels after the actual native text bottom at 300, 420 and 700 pixels, with delimiters both hidden and revealed. Twenty separate 40,000/120,000-character formatting/layout cases preserve source exactly; ordinary rich text stays formatted. The slowest tested 120,000-character malformed case takes 1.114 seconds on this machine. This is bounded-input evidence, not a general latency promise.
