# Ghostty text delivery and screenshot paste

Verified on Lenovo on 5 October 2026 with Ghostty 1.3.1, Hyprland 0.56.2, the native Mluva delivery implementation and Codex 0.160.0. The workstation's custom Ghostty configuration mapped Ctrl+Shift+V to literal Ctrl+V and Ctrl+V to clipboard text. Mluva correctly selected its terminal text chord, but that reversed binding invoked Codex's image action with a text-only clipboard.

The local repair restores Ctrl+Shift+V and Shift+Insert for clipboard text and leaves literal Ctrl+V available for TUI images. The Omarchy Super+V override retains terminal text paste and selects Ctrl+V for an advertised image format in Ghostty. Its helper probes MIME types outside the compositor, with a 300 ms timeout, and revalidates the original focused window address and process before dispatch. Other terminals retain Shift+Insert; ordinary windows retain Ctrl+V. Super+Shift+V remains the clipboard-history picker.

The maintained workstation inputs were delivered through [merged PR #22](https://github.com/1vecera/mac-bootstrap/pull/22): [Ghostty config](https://github.com/1vecera/mac-bootstrap/blob/6d767b91c6be639efb474f21a28e58876bc8404d/omarchy/workstation/config/ghostty/config), [Hyprland override](https://github.com/1vecera/mac-bootstrap/blob/6d767b91c6be639efb474f21a28e58876bc8404d/omarchy/workstation/config/hypr/clipboard.lua) and [paste helper](https://github.com/1vecera/mac-bootstrap/blob/6d767b91c6be639efb474f21a28e58876bc8404d/omarchy/workstation/bin/ghostty-paste). Mluva's delivery key selection, target guards and unconfirmed-terminal receipt remain unchanged.

## Evidence

The existing production Rust target capture and delivery functions ran against an independent raw terminal observer in a disposable Cage/Hyprland Wayland session. The original configuration produced exactly one raw Ctrl+V byte instead of text. Reloading the repaired configuration made the same native call deliver the complete Czech/emoji multiline payload in exactly one bracketed paste. The real Super+V callback delivered text once; a virtual Super+V invocation with Super held dispatched the image chord while preserving clipboard image bytes. The private compositor resolves wtype's generated keyboard by symbols for that invocation; host keyboard settings were unchanged. Wrong window and process identities produced no paste events.

The actual Codex TUI then received native automatic text delivery and accepted Super+V as an image attachment. Its saved attachment's 8-bit RGBA pixels matched the synthetic 8×8 clipboard image; the captured UI displayed the entered text and `[Image #1]`. No prompt was sent. The compact observations are in [receipts.json](receipts.json).

The session had private HOME/XDG state, session bus, runtime/Wayland sockets, PID and network namespaces, and no host input, audio or display sockets. Only a render node was exposed for the headless compositor. Scratch harnesses, logs and the synthetic screenshot stay under the worktree's private `tmp/ghostty-format-paste/`. Earlier harness failures are retained separately: inherited clipboard-daemon output pipes, missing private-seat keys, a synchronous compositor probe, TUI startup readiness and an image-depth comparison were corrected before the passing run.

The verified configuration is installed locally. Hyprland reports no configuration errors and one Super+V binding. Three existing Ghostty processes reloaded through their supported SIGUSR2 handler; they were not restarted. Installed file hashes match the reviewed configuration. Focus, pointer and window layout were unchanged in the installation readback; no host clipboard contents were read and no host key was injected.

This proves the tested native text delivery and real Codex image attachment in the private Wayland session. Physical Super+V/F9, real microphone capture, terminal pane changes, other applications and other desktops remain separate acceptance limits. A terminal receipt still reports dispatched but unconfirmed because Mluva does not read terminal content.
