# Native worker cancellation and parent failure

5 October 2026: the native Qwen runtime survived its client's abrupt death, retaining approximately 2.7 GiB of CPU RAM and a readable temporary authentication key. The prepared repair binds both runtime startup and GPU discovery to the parent's lifetime and keeps authentication bytes in sealed anonymous memory. Actual component and GTK-app crash checks now observe Qwen exit with SIGKILL and its key become unreadable. The installed/published 2.0.0 payload remains unchanged; this work is preparation in [draft PR #71](https://github.com/1vecera/Mluva/pull/71).

The later [incomplete-line comparison](#incomplete-qwen-lines-cancellation-and-recovery) directly observes a shared timeout failure: released and native clients remain pending after 195 real seconds while bytes arrive without a newline. Public cancellation still suppresses text, reaps the worker/key and permits recognition with a fresh client on both CPU/CUDA protocol routes. The total-response deadline remains ineffective for this input; this checkpoint adds evidence and native checks without changing production behavior.
