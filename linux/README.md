# Mluva for Linux

The Linux client is a native GTK 4 and Libadwaita application. For Dictation, Command, and Scratchpad it gates microphone capture on an ElevenLabs Scribe v2 Realtime readiness handshake, drains selected or automatic-default PipeWire audio into an owner-only 16 kHz mono WAV and a bounded realtime queue, shows waveform plus volatile recognition in the Capture page, and allows only provider-committed text into processing, history, or delivery. If the realtime route cannot start, keep up, or finalize, it reports one explicit batch Scribe v2 fallback from the retained local WAV. Before any mode that needs Codex can open the microphone, Mluva resolves one concrete app-server model and freezes it for the capture. Faithful cleanup then processes immutable committed segments through bounded isolated attempts while raw recognition remains visible; Command and saved-style requests use the same frozen model before reviewed copy or insertion.

The supported Fedora GNOME behavior and the security reasons for its deliberate macOS differences—an always-available in-window live surface, an optional display-only Shell bar instead of a focusable GTK overlay, and no desktop-wide typed-trigger listener—are defined in the [Fedora GNOME platform profile](../docs/linux-platform-profile.md).

## Feature maturity

The current manually accepted set is recording and transcription, recording setup controls, History, and custom saved styles. The application labels every other public capability Experimental from one shared registry and exposes the complete status in Settings → Feature maturity. The generated [feature-maturity matrix](../docs/feature-maturity.md) is the matching public description.

Automatic paste is an experimental known limitation: it is disabled by default and does not currently work reliably in the current Fedora acceptance setup. Mluva retains completed text on the clipboard for recovery. Detailed implementation and automated evidence below describe what the code attempts and proves; they do not promote an Experimental feature to manually verified.

## Supported desktop contract

- Fedora 44 with GNOME Shell 50, GTK 4, Libadwaita, PipeWire, AT-SPI, and the XDG Global Shortcuts portal for recording and cancellation
- Wayland with `wl-copy`; X11 delivery remains supported by the runtime when `xclip` and `xdotool` are installed
- Distribution Python 3.12 or later with PyGObject, plus `uv`
- Optional `codex` installation authenticated locally for Command mode and faithful cleanup
- `ELEVENLABS_API_KEY` injected into the application process through a secret manager or session service; the key is read at runtime and is never written to settings, history, logs, or diagnostics

On Fedora, the operating-system packages are:

```bash
sudo dnf install at-spi2-core gobject-introspection gtk4 libadwaita pipewire-utils procps-ng python3-gobject uv wl-clipboard
```

Install Codex and authenticate it before enabling cleanup or Command mode. Mluva starts `codex app-server --listen stdio://`, performs the required `initialize` and `initialized` handshake, pages through `model/list`, resolves a configured model ID or the single advertised default to its concrete model identifier, and aborts before microphone capture if that identity is unavailable or changes at `thread/start`. Each transformation creates an ephemeral read-only thread with approvals disabled in an empty owner-only runtime working directory, instructs the turn not to use tools, and collects streamed agent-message deltas until `turn/completed`.

## Run from the repository

The virtual environment must expose the distribution PyGObject modules because GTK bindings are compiled against the system libraries. The repository target establishes and checks that boundary before syncing the locked dependencies:

```bash
make linux-run
```

For an environment without launching the application, run `make linux-setup`. It reuses a valid environment, recreates one that cannot import GTK, Libadwaita, and AT-SPI, and refuses a stale lockfile through `uv sync --locked`.

Inject `ELEVENLABS_API_KEY` before the final command through your secret manager, desktop session service, or another mechanism that does not write the value into this repository or shell history. Mluva refuses capture when the variable is missing. On a machine that already uses the optional `daniel-ai-skills` managed launcher, `bash configure-secret-profile.sh` creates an owner-only `voice-scribe` profile containing only the reviewed ElevenLabs `op://` field reference; the launcher resolves it only inside the child process and never prints the value.

## Install for the current user

```bash
make linux-install
```

The installer refuses to replace an environment from which Mluva is still running, rejects unrecognized application or command paths, and keeps the complete previous app as a temporary rollback copy until the new production environment and desktop integrations are ready. It creates an isolated environment that can use the system GTK binding, installs an application-menu entry, and registers the desktop identity required by the XDG Global Shortcuts portal. An upgrade disables and retires the obsolete `right-alt@voicescribe.local` helper so Right Alt/AltGr returns to normal desktop use. When the optional `daniel-ai-skills` agent catalog is already installed, the installer also creates its scoped owner-only `voice-scribe` reference profile and the application launcher uses that profile only when a direct key is absent. The application and shortcut changes require no logout. On first launch the desktop asks for the F9 recording toggle and `Ctrl+Alt+Escape` cancellation bindings.

Run `mluva-uninstall` to remove the application, launchers, desktop entry, icon, optional recording overlay, and an installed keyboard helper. The keyboard helper removal may request `sudo` because its narrowly scoped systemd unit lives under `/etc`. Uninstall deliberately preserves user settings, history, recordings, and the managed credential reference under the existing `voice-scribe` compatibility directories; the command prints those retained paths instead of silently deleting user-created data.

Press F9 once to prepare and start recording, then press F9 again to stop and transcribe. The Capture page can select any unmodified key from F1 through F24; changing it replaces the immutable portal session with a key-specific recording action. F13–F24 typically have the fewest application and desktop conflicts, but most standard keyboards cannot emit them without a programmable layer, so F9 is the practical default. The desktop remains authoritative and may ask the user to approve or change the proposed trigger; Mluva displays the actual assigned trigger instead of claiming the preference won. ElevenLabs readiness and any required concrete Codex-model resolution happen off GTK's event loop. A second press during preparation cancels before the microphone starts. During capture, the in-window Live capture surface and optional bottom bar show bounded elapsed time, the exact realtime or batch-fallback route, local RMS waveform level, delivery readiness, and current raw/volatile transcript state. The in-window surface also names the selected PipeWire input. Volatile text is kept separate from the editable final-output buffer and is erased at every terminal state. The realtime client uses manual commits every 25 seconds and at Stop, and only `committed_transcript` events can become raw history, enter cleanup, or reach delivery. Stop does not finish the realtime route until the final committed segment has been dispatched to cleanup. A successful realtime result is not uploaded again through batch recognition.

The approved cancel shortcut erases active local audio without recognition or delivery; Escape does the same while the Mluva window has keyboard focus. If PCM has already crossed the realtime connection, cancellation closes without a commit and erases the local WAV, but it cannot recall audio already received by ElevenLabs; the status states which case occurred. Wayland does not allow an application to intercept an unapproved bare Escape key from another application.

**Experimental — automatic insertion.** It requires GNOME toolkit accessibility to be enabled before Mluva starts. Check it with `gsettings get org.gnome.desktop.interface toolkit-accessibility`; if it reports `false`, enable it with `gsettings set org.gnome.desktop.interface toolkit-accessibility true`, then restart applications that were already open if they still do not expose text targets. Mluva reads the live `org.a11y.Status.IsEnabled` property and stays visibly copy-only when the desktop has disabled AT-SPI instead of treating successful library initialization as permission. Even with accessibility enabled, the current Fedora acceptance setup has not produced reliable automatic paste.

Native AT-SPI editable-text insertion remains the preferred path. A non-editable target may use `wtype` on a compositor that supports its virtual-keyboard protocol, the optional Mluva `ydotoold` service, or `xdotool` in an X11 session. Installing the `ydotool` client is not sufficient: its daemon is mandatory. Mluva selects it only when the configured socket is live, owned by the current user, and owner-only; it never starts a privileged daemon or widens `/dev/uinput` access during ordinary application installation. On Fedora, install the package and then make the separate system-administration choice explicitly:

```bash
sudo dnf install ydotool
mluva-input-helper install
```

The helper runs the packaged daemon with mouse and touch capabilities disabled, exposes a mode-`0600` socket in the current user's runtime directory, allows only that `/dev/uinput` device through its systemd device policy, and stops with the user's session. Any process running as that user can still ask it to synthesize keyboard input, so remove the helper with `mluva-input-helper remove` if that same-user trust tradeoff is unwanted. Without a ready keyboard helper, non-editable targets remain recoverable copy-only deliveries.

Fedora GNOME does not implement the layer-shell protocol used by compositor-native overlay libraries, and an ordinary GTK top-level window may take focus from the captured target. Mluva therefore renders the same transient state in two places: an in-window bar that is always available, and an optional display-only GNOME Shell extension for a bottom-of-screen bar over other applications. The extension accepts no input, exposes no D-Bus methods, does not reserve screen space, and never participates in delivery. It subscribes only to a bounded per-user session-bus signal containing phase, elapsed time, mode, route, microphone level, delivery readiness, and a short volatile transcript preview; it erases every field on stop, cancellation, failure, shutdown, or application-owner loss. Other processes running as the same user may also observe session-bus signals, so remove the extension if that local-account boundary is not acceptable.

Ordinary application installation packages but does not install or enable Shell code. Opt in explicitly with:

```bash
mluva-overlay install
```

If the current GNOME Shell session has not discovered a newly installed extension, log out and back in once, then run `mluva-overlay enable`. Check it with `mluva-overlay status` and remove it with `mluva-overlay remove`. Updating an already discovered extension normally needs only disable/enable, but a first install on Wayland cannot reload the Shell in place.

The searchable settings dialog, opened from the Capture page's gear button, keeps the full **Capture mode** label visible, presents **Dictate**, **Command**, and **Notes** with complete pre-recording explanations and a tooltip that also explains the separate **Meeting** mode, shows the selected and actually assigned global recording key, and exposes **Transcription language**, **Microphone**, **Meeting system output**, **Spoken structure**, and **Automatic paste** as persisted controls. The selected capture mode carries its Verified or Experimental status beside the control, Automatic paste names its known limitation in place, and Settings → **Feature maturity** lists the complete registry. Auto-detect omits the optional Scribe language field; the listed languages use current ISO-639-3 codes, and a valid hand-configured ISO-639-1/3 code remains visible as a custom choice. Audio routing reads a bounded `pw-dump` metadata snapshot without opening a device, stores only the selected `node.name`, and passes it as a direct `pw-record --target` argument; missing persisted devices stay visibly unavailable instead of silently changing. Refresh is blocked during capture or retry. Spoken structure deterministically converts explicit punctuation, “new line,” “new paragraph,” and “scratch that” phrases for Dictation and Notes while retaining ElevenLabs' exact recognition beside the prepared form in History; Command instructions remain literal. Automatic paste remains restricted to captures begun with the approved global function key, while button captures are copy-only. Ordinary Dictation uses the latest authoritative global AT-SPI focus event, excludes password roles, and captures selection offsets without reading target text. Delivery restores that exact target, installs the complete transcript on the clipboard, then prefers the target's native editable-text interface and trusts libatspi's explicit success result; only a target that explicitly lacks native editing may receive one keyboard paste fallback. A content-free caret check distinguishes a confirmed keyboard fallback from an unconfirmed dispatch; uncertainty is stored as `paste-unconfirmed`, never triggers an automatic retry, and leaves the complete text on the clipboard for inspection and manual recovery. If focus-event registration, target capture, or restoration fails, delivery is copy-only. Browsers and Electron applications that do not publish renderer accessibility objects are intentionally copy-only; launch them with their supported renderer-accessibility option when automatic delivery is required.

The **Personalization** tab manages owner-only dictionary replacements, explicit snippets, and saved output styles. Dictionary matching is case-insensitive, whole-phrase, and longest-first, with either a fixed written form or capitalization matched to the spoken phrase. Application-specific rules override the same global phrase using a local executable identity. Small corrections explicitly saved in History appear as review-only vocabulary suggestions in the same local application scope; repeated corrections are grouped, broad rewrites are rejected, and each suggestion must be added or dismissed by the user. No ordinary transcript transformation or unreviewed suggestion changes the dictionary. Spoken snippets expand only after the explicit word “snippet” and support `{{date}}`, `{{time}}`, `{{datetime}}`, and `{{weekday}}`; unknown variables remain visible. Exact single-token typed triggers are stored and covered by the same scoping and rendering rules, but desktop-wide typed expansion is deliberately disabled until Linux has a secure Wayland input boundary that can exclude password fields without broad keystroke capture.

The Capture settings expose **Faithful**, Message, Google Chat, Tasks, Email, Prose, Technical notes, Prompt, and custom output styles, with the selected mode's complete instructions visible and repeated in its hover description before recording. A **Manage** action there opens custom-mode creation and editing in Personalization; built-ins are immutable. Mluva freezes spoken-structure, dictionary, snippet, variable, protected-vocabulary, cleanup, style, privacy, retention, and destination inputs before capture, so later preference edits cannot alter active work. For successful realtime recognition, deterministic preparation and Faithful cleanup run per immutable committed segment with two concurrent isolated Codex clients, eight queued segments, an eight-second attempt timeout, and a two-second Stop drain. Results become publishable only in capture order; timeout, cancellation, capacity pressure, malformed or oversized output, provider failure, or protected-token changes select that segment's exact raw recognition. Batch fallback uses one bounded whole-transcript cleanup request with the same exact-raw fallback, while saved style is applied once after ordered cleanup. Application identity is used only for local rule and mode selection and is never included in a Codex request. **Remember mode and style per application** is opt-in and applies only to captures begun with the approved global function key, where an external target can be identified without reading its text.

Command mode captures the focused text selection or caret through the desktop's AT-SPI accessibility bus when recording starts from the global shortcut. It sends Codex only the bounded spoken instruction and up to 2,000 characters of explicit selected text—never the application name, window title, or nearby text—and shows the proposed result before any delivery. Accept restores the captured focus plus selection or caret before attempting replacement; if the target cannot be restored, Mluva copies the reviewed result instead. Password fields and oversized selections fail closed. Starting Command mode from the Mluva window has no external target and therefore produces a copy-only preview.

## Experimental Fedora GNOME acceptance backlog

These checks are the remaining human promotion gate for Experimental desktop behavior; they are not current pass claims. Launch `mluva`, approve the proposed F9 recording toggle when the desktop asks, and wait for the Capture page to report **Ready — press F9 once to start and again to stop**. Use a synthetic phrase with no sensitive content, leave **Automatic paste** enabled, and focus the target field before pressing F9. Automated checks must not synthesize these gestures, open approval dialogs, or take over the user's screen.

| Check | Action | Pass condition |
|---|---|---|
| Native auto-paste | In GNOME Text Editor, press F9, wait for capture readiness, speak once, then press F9 again | The finished text appears exactly once at the original caret or selection; History records a confirmed delivery receipt |
| Toggle behavior | Press F9 once while idle, then once while recording | Exactly one capture starts and the next activation stops it exactly once |
| Alternate function key | Select another key from F1–F24, approve the replacement if prompted, and use it once to start and once to stop | The new key controls capture, the status displays the desktop's actual binding, and F9 no longer controls the replaced action |
| Recording overlay | Install and enable the optional overlay, focus another application, and start then stop a synthetic capture with F9 | A noninteractive bar appears near the bottom without moving keyboard focus; it shows preparing/recording status and disappears immediately on Stop |
| Global cancellation | Start a synthetic capture, then press the approved `Ctrl+Alt+Escape` binding | Capture ends without recognition, History, insertion, or retained local audio |
| Button boundary | Start and stop Dictation with the visible application button | Finished text is copied for manual paste and is never automatically inserted |
| Password exclusion | Focus a disposable password field and dictate a non-sensitive test phrase | Mluva does not insert into the field and reports copy-only recovery |
| Browser or Electron target | Focus an ordinary editable field and dictate once | An accessibility-enabled renderer inserts once; an inaccessible renderer reports copy-only rather than guessing or injecting |
| Terminal, editor, or rich text | Dictate once into each representative target | Native insertion may confirm; a keyboard-only fallback is dispatched at most once and remains `paste-unconfirmed` when a content-free caret check is unavailable |
| AltGr behavior | Type one normal AltGr character while Mluva is running | Right Alt/AltGr retains its normal keyboard-layout behavior and no helper listener exists |

If the shortcut does not reach Ready, report the Capture-page status and inspect the desktop's application shortcut settings. The on-screen button remains copy-only and usable without a global binding. Changing a key is desktop-mediated and may require explicit approval, but it never requires a logout.

## Experimental: explicit Meeting capture

Meeting is a separate tab and cannot be selected as a remembered/default dictation mode. It starts only from the visible **Start Meeting capture** button; the global function key cannot start, stop, or silently switch into Meeting. Escape while the Mluva window is focused cancels both Meeting streams and erases their files without upload.

An explicit Meeting starts two fixed-format `pw-record` processes: the selected (or automatic default) microphone and the output monitor of the selected (or automatic default) PipeWire sink via `stream.capture.sink=true`. The configured route names are visible on the Meeting page before capture. “System audio” therefore means all audio currently playing through that sink, not one chosen window or application. The installed Fedora portal exposes no audio-capable ScreenCast contract, so this client does not claim per-window audio selection or a portal-mediated audio grant. If one source fails but the other contains valid audio, Mluva preserves the valid source and records a visible warning; if both fail, it stops before recognition.

After Stop, Mluva averages aligned mono PCM16 samples locally, preserves any longer source tail, and uploads only the finalized WAV to ElevenLabs Scribe v2 with word timestamps and diarization enabled. Speaker labels are therefore available after batch finalization, not as a live partial transcript. Meeting never invokes dictation delivery, clipboard copy, automatic paste, Codex cleanup, saved styles, or application targeting. Copying a completed transcript is a separate explicit archive action.

Outside Incognito, the mixed WAV, transcript, available speaker segments, literal three-sentence summary, explicitly marked decisions/actions, actual captured sources, provider metadata, and warnings live in an owner-only Meeting archive separate from dictation History. A provider failure creates a controlled failed record and retains its managed WAV for **Retry transcription**; retry updates the same record and still performs no delivery. Records can be renamed, exported as owner-only Markdown or JSON, or permanently deleted with only their validated managed recording. Incognito still uploads the finalized audio to ElevenLabs, then erases the audio and creates no Meeting record whether recognition succeeds or fails.

If the compositor does not approve or provide the Global Shortcuts portal, both global recording and global cancellation are unavailable; the record button remains functional and intentionally copy-only. If no supported input injector is installed, successful text remains safely on the clipboard with manual-paste guidance rather than claiming insertion succeeded.

## Recovery and history

Every completed transcription keeps both the immutable ElevenLabs recognition and the delivered form in an owner-only SQLite history database, along with the locally captured application scope when one was available. Each entry records the controlled recognition route—Scribe v2 Realtime, Scribe v2 batch, or batch retry—and, when applicable, one of three reviewed fallback categories: unavailable, startup failure, or stream/finalization failure. Enhanced entries additionally record the `codex-app-server` provider ID, full concrete model identifier, disclosed context kinds—including an explicit **None** when no context was sent—controlled completed/raw-fallback/safe-fallback/failed outcome, and recognition, enhancement, and delivery milliseconds. Command and Notes leave delivery timing empty until the explicit acceptance action occurs. Raw provider exception text is never stored as route or outcome metadata. The History tab exposes this provenance and timing, can rename an entry, explicitly correct the delivered form without delivering it, copy either form, reprocess immutable raw recognition through the current local deterministic rules, restore the raw transcript, export owner-only Markdown or JSON, and permanently delete the selected entry after confirmation. Its separate **Copy** and target-gated **Paste again** actions reuse a bounded session-only focus/offset target when the exact AT-SPI object remains restorable, dispatch at most once, and confirm without reading text; the application stores no selected-text content in that cache, and **Paste again** becomes unavailable after restart or when the target is stale. The first pre-edit form remains the comparison baseline across later edits; reprocessing, restoring raw recognition, or retrying recognition clears prior enhancement and delivery evidence that no longer describes the selected text. Normal dictation audio is erased after successful delivery.

Recognition, Codex processing, and desktop delivery failures are stored as distinct history outcomes outside Incognito. A delivery failure keeps the recognized text so copying it again does not repeat recognition. When policy-retained audio belongs to a recognition failure, **Retry transcription** safely validates the managed path, calls Scribe v2 again, and stops at a `retry-ready` history preview; it never copies or inserts automatically. A later explicit copy updates the receipt and erases failure-only audio, while Always keeps it.

Scratchpad is deliberately acceptance-gated: a successful capture opens as an editable draft without reading or changing the desktop clipboard. Mluva persists that draft and its source WAV under the XDG data directory, restores it after relaunch even when network credentials are unavailable, and blocks another recording until the user explicitly chooses **Copy and resolve** or **Delete draft**. Resolving or deleting the draft erases its recovery audio.

The Capture tab exposes the same bounded privacy controls as the product contract. **Keep audio** supports Never, Failures (the default), and Always. **Keep history** supports Forever, 7 days, 30 days, and 90 days; pruning also erases managed recovery audio but never removes an unresolved Scratchpad row. **Incognito** makes new sessions write no transcription history or persistent Scratchpad state and erases session audio even when Keep audio is Always. Linux realtime recognition sends microphone chunks to ElevenLabs during capture; batch fallback, Meeting, and retained-audio retry upload finalized recordings. The UI states that cloud boundary explicitly. Codex cleanup, Command mode, and saved styles fail closed in Incognito because the installed app-server cannot currently prove that its own session state is ephemeral; deterministic local dictionary and spoken-snippet processing remains available.

The local diagnostics ledger is bounded to 5,000 controlled events and records capture readiness/duration, recognition, enhancement, preview/delivery, provider category, outcome, and milliseconds. It has no columns for transcript or selected text, audio or paths, clipboard content, target identity, device names, window titles, credentials, or arbitrary exception messages. Incognito sessions write no diagnostic events. **Export** writes an owner-only JSON artifact containing the same controlled event fields and non-secret configuration booleans; even an explicitly configured Codex model is represented only as `codex_model_configured: true`, while selected audio targets are reduced to configured/not-configured booleans.

## Verification

```bash
make linux-test
make linux-shortcut-test
make linux-overlay-test
make linux-text-target-test
```

`linux-shortcut-test` runs the production GlobalShortcuts client against a synthetic portal peer on a private D-Bus daemon. It proves host-app registration, race-free request paths, F9 plus cancellation binding, actual-trigger propagation, duplicate-activation suppression, release re-arming, session filtering, and teardown without contacting the live portal or generating a key event.

`linux-overlay-test` packages the real extension and runs preparing, active-speech, and quiet/no-speech states inside a private session bus and a headless GNOME Shell 50 virtual monitor. It asserts that the bar starts hidden, does not accept pointer input, preserves keyboard focus, remains within the monitor, hides on a terminal state, and stays hidden after the application bus owner vanishes; retained screenshots live under `tmp/overlay-smoke/`. It does not install or enable the extension in the user's live Shell session.

`linux-text-target-test` starts a separate synthetic GTK target and Mluva's production AT-SPI client inside fresh Xvfb, D-Bus, XDG, and accessibility namespaces. It proves global focus-event capture, target restoration, editable-interface discovery, exact Czech Unicode insertion, and final caret placement, then retains a JSON receipt and screenshot under `tmp/native-text-target-smoke/`. It requires `xorg-x11-server-Xvfb` and ImageMagick's `import` command and never connects to the active display, session bus, accessibility tree, clipboard, or input devices.

The suite exercises the ElevenLabs multipart request against a local HTTP server; Scribe v2 Realtime authentication, query, PCM event, volatile/final/committed separation, final-commit cleanup dispatch, manual long-capture commits, bounded-queue overload, sanitized errors, cancellation, and controlled batch-route persistence against local WebSocket servers or synthetic connections;
