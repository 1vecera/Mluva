# Native Rust implementation

This workspace is the in-progress replacement for the released 1.6.0 application. `mluva-core` implements settings and migrations, deterministic spoken commands, SQLite history/conversations, retention and exports, screenshot ownership and frozen visual input, prompt/style overrides, bounded titles, unresolved Scratchpad recovery, personalization, vocabulary suggestions, Markdown parsing, source-preserving word edits, clipboard-first delivery and content-free Hyprland terminal identity. `mluva-gtk` provides the native application window, command catalog/search, settings navigation, document widget, personalization page, shared prompt editor/discovery, theme controller and native accessibility focus/text targets. `mluva-audio` provides native PipeWire PCM recording/streaming, Meeting mixing and partial-source warnings, device catalogs and memory-backed crash cleanup. `mluva-providers` provides compatible HTTP/SSE speech and rewriting, ElevenLabs batch/Meeting and realtime WebSocket sessions, isolated Codex JSONL sessions, the shared rewrite factory, cached speech credentials, pinned model/Qwen runtime assets and the owned Qwen loopback client. Complete application assembly, remaining physical model/fault acceptance, broader accessibility/browser/Wayland insertion and distribution remain tracked in [the acceptance matrix](../docs/rust-port-parity.md).

The authorized native model lineup is Whisper Tiny, Parakeet v3 and Qwen3-ASR 1.7B, with Qwen as the default. Existing Whisper Base/Small/Turbo selections migrate to Qwen and reopen setup; loading preserves the settings file and all existing model caches. Retained artifact metadata and the frozen release fixtures stay unchanged.

`mluva-workflows` joins finalized batch/realtime recognition, frozen deterministic rules, optional cleanup/styles or Command, clipboard/target delivery, diagnostics and recovery History. [Independent recording evidence](mluva-workflows/tests/fixtures/README.md) compares 70 complete released workflow cases and seven actual GTK target workflows, including real loopback provider requests, one insertion, stale focus, review-only modes, Incognito and retry previews. The native speech factory selects only the requested transport; capture uses a resolved rewrite model independently of document rewrite speed/thinking settings. GTK snapshots stay on their owning main context. Complete capture UI, scheduling and application lifecycle are still pending.

An explicitly executed [real Qwen inference check](mluva-providers/tests/fixtures/qwen-inference-evidence.md) now matches released CPU/NVIDIA Vulkan recognition, provisional callbacks, restart and cancellation on public English/Chinese clips, including multiple 25-second blocks. It uses disposable model/runtime/shader stores and observes actual child arguments, private key modes and cleanup through `/proc`. It requires FFmpeg, public asset downloads and compatible NVIDIA Vulkan hardware; ordinary Cargo tests ignore it.

`mluva-asr` implements native Whisper Tiny and Parakeet TDT preprocessing, vocabularies/decoding and an owned offline ONNX worker. [Independent checks](mluva-asr/tests/fixtures/README.md) cover 22 CPU preprocessing cases, 60,058 individual vocabulary IDs, 1,200 joined-token cases and sixteen actual pinned CPU/NVIDIA CUDA recognitions matching the unchanged release. Physical comparisons now use the public native client factory and verify metadata, retained/restarted weights, explicit reaping and cancellation during actual loading; NVIDIA telemetry independently confirms owned compute contexts. [Native client checks](mluva-providers/tests/fixtures/local-asr-evidence.md) add 230 independent process/protocol sessions, request-abort recovery, concurrent cancellation and actual 180-second/5 GB faults. [Native runtime provisioning](mluva-providers/tests/fixtures/onnx-runtime-evidence.md) installs checksum-pinned native libraries and notices without an interpreter, with private staging, storage budgets, cancellation and atomic replacement. Complete controller/UI integration, broader audio/fault acceptance and distribution remain required; these component checks do not replace the installed app.

The native conversation workspace now joins editable source/rewrite documents, compatible History search and merges, local prompt overrides, live source/draft/Questions panes, screenshot shelves and offline Mermaid textures. [Independent page/document evidence](mluva-gtk/tests/fixtures/conversation-page-evidence.md) records 113 page/scroll states, 70 parser/forecast observations and six actual diagram states matching the unchanged release. Empty saved titles fall back to recognition text; failed saves retain drafts. The comparison positively confirms a database merge and preserves immutable recognition. This is the actual workspace widget; capture/settings/session controllers and complete application assembly remain pending.

Build with Rust 1.95 and the platform development libraries for SQLite, OpenSSL, GTK 4.12 or later, Libadwaita 1.5 or later, WebKitGTK 6.0, libatspi and Fontconfig. The private input comparison example also needs X11 and Xtst. From the repository root:

```sh
cargo test --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
```

The checks operate on synthetic fixtures and temporary files. For task-local scratch storage, create `tmp/native-tests` and set `TMPDIR` to its absolute path when running tests. Cargo tests use the [frozen released core outputs](mluva-core/tests/fixtures/README.md), [audio/process observations](mluva-audio/tests/fixtures/README.md) and [native widget observations](mluva-gtk/tests/fixtures/README.md) without invoking an interpreter or importing the reference application. The audio checks require Linux `/proc` and memory-backed `/dev/shm`; they create their own owner-only staging and signal only isolated fixture groups. They never open an audio device. Cargo builds the synthetic audio peer and production cleanup helper for the checks; distribution must select production binaries explicitly. The installed 1.6.0 application remains the usable reference while parity is established.

The desktop tests are ignored by ordinary Cargo runs because they must have an isolated display, session bus, accessibility registry and data directories. Build the guarded private input helper and separate GTK target, then run the tests on an unused private display with the dependencies checked by `dev/run-isolated.sh`:

```sh
cargo build --locked -p mluva-gtk --example private_input --example text_target_peer
test ! -e /tmp/.X11-unix/X173
env OFFSCREEN_ENABLE_ATSPI=1 OFFSCREEN_DISPLAY_NUMBER=173 \
  XDG_CURRENT_DESKTOP=offscreen GDK_SCALE=1 GDK_DPI_SCALE=1 \
  GTK_A11Y=atspi GDK_DEBUG=no-portals \
  dev/run-isolated.sh tmp/native-document-widget -- \
  cargo test --locked -p mluva-gtk --test document_widget \
  --test prompt_editor --test application_shell --test text_target -- \
  --ignored --test-threads=1
```

Serialize desktop comparisons. Run the released reference and native surface sequentially inside one private session; automatic Xvfb display selection can race between concurrent helpers. The fixture records GTK 4.22.4 and Pango 1.58.2, and the test explicitly refuses changed renderer versions until new observations are collected from the unchanged release. Mixed CR/LF input currently triggers the same Pango cursor warning in both implementations; the recorded source, text, tags, layout and selection observations still match. This component evidence does not establish complete application parity or a performance improvement.

The separate [Firefox comparison](mluva-gtk/tests/fixtures/firefox-target-evidence.md) connects the native tracker to production clipboard/key delivery in 21 real browser cases. A separate DOM observer verifies exact final text, UTF-16 carets/selections and paste/input events; actual xclip reads verify full clipboard bytes. Cold capture, moved selections, changed/own focus, late keyboard revalidation, password/read-only fields, refused paste, NUL truncation, rich text and Command selection limits match the unchanged release. Firefox 154.0/build 20260818182641 is pinned. The supported AT-SPI debug setting disables direct peer connections so three explicit Command reads provide positive monitor controls; the privacy observation is scoped to that transport. Build the browser peer and run it only inside the additional private network/PID/device boundaries, with Firefox, Openbox, xclip, xdotool, bubblewrap and the normal GUI dependencies installed:

```sh
cargo build --locked -p mluva-gtk --example firefox_text_peer
bash dev/run-isolated-browser.sh tmp/native-browser -- \
  cargo test --locked -p mluva-gtk --test browser_target -- \
  --ignored --test-threads=1
```

The browser runner clears inherited credentials, uses a fresh home/profile, hides device nodes, blocks external networking and session-service auto-activation, and starts its own display, buses and window manager. Software EGL selection avoids an NVIDIA initialization crash when real GPU devices are hidden. Default direct-connection behavior, broader browsers/editors, Wayland and complete recording/preview/retry workflows still require acceptance. The browser peer and HTML target are development support and must not ship.
