# Mluva: hold to talk to a named Herdr agent

## Intent

Let Daniel choose a named Claude Code or Codex session from a compact dropdown in Mluva, hold a global shortcut to speak, and send the completed message directly to that session without switching windows. After recognition finishes, show the message and recipient for two seconds; send automatically unless Daniel cancels or keeps it as a draft. Optionally speak one natural sentence about the agent's response or current activity using ElevenLabs v4 Turbo.

This should work alongside Daniel's separate chief-of-staff setup. A chief-of-staff session can become another selected recipient; direct access to individual agents must remain useful without it.

## Output format

Deliver a reviewed implementation branch and draft PR in [Mluva](https://github.com/1vecera/Mluva), with focused automated tests, an isolated end-to-end demonstration against disposable Codex and Claude Code sessions, main-editor and failure-state screenshots, and concise setup/recovery documentation. Identify any required Herdr protocol change in a separate reviewable dependency. Record actual tested versions, platform limits, and measured timings rather than claiming physical-key or provider proof from mocks.

Completion means a dictated message reaches only the selected session and is submitted, cancellation reliably prevents submission, uncertain delivery never causes an automatic duplicate, and spoken feedback describes supported evidence from the intended agent. Retain a visible text reply and an independent mute control when voice is unavailable. This document specifies the next feature; it does not itself implement or enable routing or paid speech.

## What to maximize

- **One simple interaction.** Put an accessible recipient dropdown beside the editor's useful controls, showing the same agent name as Herdr plus enough project, machine and session context to distinguish duplicates. Remember the choice, show its availability, and make “no agent selected” understandable. A separate configurable hold shortcut starts this mode; existing dictation shortcuts keep their behavior.
- **Predictable sending.** Keep the selected destination fixed when recording starts. This never stops or pauses the recipient agent. The working assumption is that releasing the held shortcut ends speech; a pause while holding does not send. When the final transcript is ready, show “Sending to [name]” with a full two-second countdown. Cancel works during recording, recognition and the countdown. A second configurable action, **Keep draft**, stops automatic submission and leaves editable text. Editing or changing recipient also disarms the send. Empty or failed recognition never submits. A new recording disarms an older pending send.
- **Continuity without window manipulation.** Deliver through Herdr's supported prompt transport, including its submit behavior, while Daniel stays in his current application. Support ready and working agents without interrupting a running task; report acceptance separately from completion. A blocked permission prompt, unavailable recipient, changed session or unconfirmed delivery leaves recoverable text and a clear next action. A lost hotkey release, screen lock or application restart must never create a delayed surprise send.
- **Useful, quiet spoken feedback.** When enabled, play one brief, natural sentence about a meaningful result or blocked state for the submitted message; a “Read status” action can summarize current activity on demand. Include the agent name when needed for clarity. Prefer a correlated native reply; otherwise describe only observed activity and say when completion is unknown. Avoid narrating every terminal update. Starting another recording stops playback and prevents the app's voice from becoming a new outgoing message. Keep reply text visible and offer replay/mute.
- **Evidence that matches the promise.** Exercise duplicate names, rename/restart/exit during the countdown, busy and blocked agents, cancellation at the deadline, repeated keys, disconnect before and after acceptance, late replies after a recipient change, and TTS failure. Prove the chosen target receives one submitted message and other sessions receive none. Measure release-to-final-text, the intentional two-second grace, submit-to-receipt, reply-to-first-audio and total time separately; include sample size and p50/p95. Verify real Wayland hold/release permissions and natural English/Czech voice quality when the necessary device and credentials are available, and name missing proof honestly.

## Hard constraints

- **Bind delivery to the selected session.** Names and pane positions are display labels, not sufficient identity. Pin the machine, Herdr server/session and actual agent instance; validate the same occupant atomically when submitting. Use a bounded submission identity/receipt so retry cannot duplicate accepted text. If the installed API cannot provide those guarantees, add the minimum reviewed integration support or keep automatic sending unavailable with a precise explanation. Never fall back to foreground focus, clipboard paste, arbitrary key injection, shell input, or approval of an agent's permission request. A timeout after submission is “Delivery unconfirmed,” not permission to resend.
- **Preserve local-first trust.** Keep the chosen native recognition route, models, original transcript, settings and recovery behavior. Account login is not required. Respect Incognito, retention and account-sharing choices; agent delivery is explicit text disclosure to that recipient. Send only the bounded spoken sentence to ElevenLabs, never microphone audio or terminal history as part of speech output. Keep credentials out of process arguments, logs, source and screenshots; constrain any summarization to the selected reply/activity and treat terminal content as data, not instructions.
- **Keep the scope and authority clear.** Implement native Linux routing first, using isolated sessions for verification without disturbing Daniel's visible desktop or active agents. Preserve their existing tool/approval policies. Do not build or provision Daniel's chief-of-staff system, broaden account access, or deploy a new relay. Branches and draft PRs are the handoff; merging, releasing, replacing the installed Herdr, and enabling ongoing paid usage require the applicable explicit authorization. Browser limitations must be stated rather than emulated with unsafe desktop control.

## Soft constraints

- Reuse Mluva's Rust/GTK capture, editor, history, shortcut infrastructure and visual language, with a compact recipient control and generous clear Cancel/Keep draft actions. Avoid a separate agent dashboard or a new general-purpose automation layer.
- Prefer Herdr's versioned API and native agent events to terminal scraping. Support existing machine/session connections when exposed reliably; a local Lenovo scope is acceptable initially if visible in the picker. Do not make the first useful release depend on a chief-of-staff agent.
- Use the requested `eleven_v4_turbo` and a chosen voice through the documented Text-to-Dialogue WebSocket. Keep text-only operation available, bound synthesis and summarization work, and make the optional cloud voice choice explicit. The existing default speech provider is not a reason to substitute another TTS model silently.
